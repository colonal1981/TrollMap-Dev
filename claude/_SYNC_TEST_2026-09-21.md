# Sync test — does a repo doc reach the project?

2026-09-21. Personal use only, not for distribution or resale; not for navigation.

This file exists to answer one question and is safe to delete once it has.

**THE QUESTION.** The project's GitHub sync is configured `{"/":"include", ...}`, so a file
committed anywhere in the repo except `/researchdocs/` should appear in the project's knowledge.
If that holds for `claude/*.md`, then the repo becomes the single home for these documents:

    write the .md to TrollMap-Dev/claude/  ->  it is on Ryan's drive immediately, in git with
                                              history, and greppable in 1.5 seconds
    commit and push                        ->  the sync carries it into the project knowledge
                                              with no second write and no export extension

**WHAT TO CHECK.** After this is pushed and the sync has run, call `project_info` and look for
`claude/_SYNC_TEST_2026-09-21.md`.

    it appears exactly once   -> the repo is the home. Move the other 321 docs in and stop
                                 using project_write for new ones.
    it appears twice, or a    -> project docs and synced repo files are separate collections.
    doc that already exists      Then the repo is still worth it for the drive copy and the git
    as a project doc            history, but a doc must live in ONE of the two and not both.
    duplicates
    it never appears          -> the sync does not cover this path. Keep writing project docs,
                                 and keep a drive copy by writing the file first and uploading
                                 it with project_write's local_path, which is how
                                 00_START_HERE.md was updated on 2026-09-21.
